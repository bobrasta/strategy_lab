### Volume profile tool (2026-10-12)
At the user's request: draw a fixed range volume profile on the chart, as in TradingView / MT5 tools.
- **Use:** the toolbar's profile button (next to Fit), then drag from the first candle to the last, or click both; a band shows the bars and times while drawing, a hint pill says what to do (Esc cancels). One range per pick. The result is a `volume_profile` instance (`IndicatorsState.addProfile`) with `RangeFrom` = first candle open, `RangeTo` = last candle open + the chart timeframe (exclusive), `YYYY.MM.DD HH:MI` UTC, so the engine computes it (≈1–2 s, then cached) and it is listed, persisted and edited like any indicator.
- **Edit:** hover a profile's left/right edge (within its drawn price box) → resize cursor; drag to resize (`setProfileRange`, recomputed; an edge can't cross the other). A click inside the box selects it (handles shown), Delete/Backspace removes it. A trade under the click wins over a profile.
- **Rules:** a range never reaches past the replay cursor; nothing about the profile is computed in Dart (the time inputs are only parsed to place the edges, with the engine's `StringToTime` rules: `lib/indicators/input_time.dart`). If `volume_profile` isn't built, the instance waits (`unbuilt`) and the build starts; it is computed when the build succeeds.
- **Code:** `lib/chart/volume_profile_tool.dart` (`VolumeProfileTool`: state, gestures, band/handle painting), wired through `PriceChart(tool:)` (drag starts at pointer-down, `DragStartBehavior.down`), `ChartToolbar`, `VolumeProfileHint`, Esc/Delete in `main.dart`.
- **Tests:** `test/volume_profile_tool_test.dart` (time inputs vs the engine's rules; drag both ways, click-click, Esc, pan without the tool, resize by the edge with the hover cursor, select/deselect/Delete, replay clamp, not-built → build → compute; fake engine). Real engine: `integration_test/volume_profile_tool_test.dart` (40 M15 candles dragged with the mouse on the full data file → the engine's profile: every row/line inside the selected candles' time span and high/low, POC/VAH/VAL present; right edge dragged 10 bars → recomputed; Delete). Screenshots of the band mid-drag and the selected profile checked.

## Decisions

- Results drawer at the bottom (MT5 tester tabs), Tester settings in the right drawer, both overlaying the chart as the FVG Lab drawers did.
- The trades layer draws the **initial** SL/TP: later modifications are only known from `sl_final`/`tp_final` at the exit, so drawing them earlier would leak the future.
- Report fields that MT5 shows as percentages but the engine doesn't write (long/short won %) are shown as counts. Compare has no difference column.
- Graph buckets are min/max picks of rows parsed to plotting precision; every number shown as text (hover, readouts) is an exact row read with `double.parse`-identical parsing.
- A confirmation covers only the period it was made for; changing a strategy's protected period asks again. Weakening or removing a protection asks once more.
- History reads `runs/` directly (not `list_runs`), so it works while the engine is down.
- Chart candles stop at the run's last simulated bar; bars after the run are never shown with it.
- Integration tests run in debug mode, where JIT warm-up adds UI pauses; the stall budget is checked in profile mode (`flutter drive --profile`).

- **Indicators (M7):** instances store only non-default inputs (as the Tester), so the label lists exactly those and a rebuilt indicator's new defaults apply. Add is enabled for an indicator with an `.so` (built or stale), like Start for strategies; stale is flagged gold. Indicators are computed on the whole data file, not the run's From/To, so the cache key doesn't depend on the run and switching runs on the same file costs nothing; the display rule cuts them at the chart's end. `profile` is sent as the Tester's profile path. Editing inputs clears the old output at once (old values never show under the new label); a successful rebuild recomputes the instances but keeps the old lines until the new output arrives. Plot points of a finer timeframe than the chart's are placed inside the chart bar by time; the price autoscale stays on candles only.
- **Indicator protocol details the engine must match** (the client also accepts the alternatives noted): `indicator_inputs` → `{schema, plots}` with `schema` = the `hummer inputs` object (its `inputs` list is read; a bare list is accepted too) and `plots` = `[{index, name, label, color, style, width}]`; `start_indicator` → `{job_id, out, cached}`; events keyed by `job_id`; `indicator_progress` like `run_progress` (`pct`, `sim_time`, `stage`); `indicator_finished` `{job_id, status ok/failed/stopped, out, cached, exit_code, signal, error, journal_tail, stderr_tail}`; `unknown_method` as the error code of a method the engine lacks. `plots.csv`: header line `stamp,plot,time,value` (optional for the parser), times `YYYY-MM-DD HH:MM:SS`, plot as a decimal index, empty value = EMPTY_VALUE (a number ≥ 1e300 is read as EMPTY_VALUE too), rows in emission order. `indicator.json`: `plots` (as above) and `warnings` (list of strings) are read; everything else is shown nowhere yet.
